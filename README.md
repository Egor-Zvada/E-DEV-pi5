# E-DEV 1.0 · Raspberry Pi 5

Домашний dev-сервер и маршрутизатор: Wi-Fi с AmneziaWG 3, системные контейнеры Incus, две панели и SMB-файлообмен. Все настройки собраны в **`e-dev settings`** — терминальном меню с ASCII-логотипом, стрелками, Enter, Space и Esc. Система работает самостоятельно: скрипты, systemd, локальные конфиги и кэш; Mac и AI после установки не нужны.

**Целевая система:** Raspberry Pi 5, Raspberry Pi OS Lite **64-bit**, Debian **13 / trixie**, от 4 GiB RAM. Первоначальная установка через Ethernet. Встроенный `eth0` закреплён в IN, `wlan0` в OUT; USB Ethernet/Wi-Fi можно добавить позже.

## Главное меню

| Раздел | Настройки |
|---|---|
| **LAN / IN** | Источники интернета, DHCP/статика, Wi-Fi dongle, основной вход, резервы, автопереход |
| **OUT** | Добавление и освобождение дополнительных портов общей сети |
| **AP** | Имя/пароль Wi-Fi, диапазон/канал, подсеть, DHCP, DNS, режим трафика, Hybrid Settings |
| **VPN** | Туннель, DEFAULT/MANUAL/AUTO, импорт/замена/переименование/удаление конфигов, измерения |
| **Статус** | Живой дашборд; `q` возвращает в Settings |
| **Доступ и пароли** | SSH, LXConsole, SMB, внешний Incus UI, сертификаты и общий пароль |

Подсеть, DHCP, DNS и режим трафика AP общие для **всей OUT-сети**, включая проводные порты. Отдельная смена пароля Wi-Fi находится только в AP. Общий пароль меняется в «Доступе» или через `e-dev passwd all`.

## Команды

```text
e-dev settings          настройки
e-dev status            живой дашборд
e-dev status --once     текстовый статус
e-dev links             текущие IP-ссылки на панели и файлы
e-dev wifi clients      подключённые клиенты, IP и MAC
e-dev wifi status       AP и режим трафика
e-dev lan status        входы интернета и OUT-порты
e-dev vpn status        профиль, туннель и handshake
e-dev speedtest         скорость активного VPN
e-dev diagnostics       состояние постоянного регистратора
e-dev diagnostics last  последний снимок
e-dev passwd all        общий новый пароль SSH / UI / SMB / AP
e-dev manuals           инструкция с выбором глав
man e-dev               системная man-страница
```

`e-dev help` показывает только этот короткий список. Старые публичные команды настройки убраны; прямой `vpn add NAME FILE` сохранён для импорта и описан в главе VPN. Tab в оболочке дополняет актуальные команды и путь файла в `vpn add`. Алиасы команды: `E-DEV`, `E-dev`, `edev`.

Если SSH-сессия открыта до обновления до 1.0, один раз выполните `source /etc/bash_completion.d/e-dev` или перезайдите. Дальше Tab сам подхватывает обновления списка команд. В Settings логотип сохраняет рамку и пропорции на разных размерах окна; при возврате остаётся выбранный раздел.

`e-dev manuals` открывает главы по разделам меню, контейнерам, файлам и диагностике. В тексте доступны стрелки, PgUp/PgDn, `/` поиск и `q` назад. Полная инструкция: [COMMANDS.md](docs/COMMANDS.md).

## Установка на новую Pi

1. Записать Raspberry Pi OS Lite 64-bit, включить SSH и создать обычного пользователя с `sudo`. Подключить Ethernet и питание.
2. Найти IP Pi в DHCP-клиентах роутера и войти по SSH.
3. Установить проект:

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/Egor-Zvada/E-DEV-pi5.git
cd E-DEV-pi5
sudo ./install.sh --country RU
```

`--country` должна соответствовать стране использования Wi-Fi. Доступны `--user USER --hostname E-DEV --ssid E-DEV --timezone Asia/Sakhalin`; по умолчанию пользователь, запустивший sudo. Установщик проверяет модель, архитектуру, Ethernet и пересечения сетей. Затем ставит зависимости, собирает AWG из закреплённых исходников, создаёт Incus, панели и шару.

Общий пароль SSH/SMB/LXConsole/AP запрашивается скрыто: 8–63 печатных ASCII-символа, без передачи через argv. В Git нет пароля по умолчанию. Установка рассчитана на чистую Pi OS; существующий E-DEV/Incus с данными не перезаписывается. После прерванного начального bootstrap допускается повторный запуск. Снимки прежних настроек: `/opt/e-dev/backups/install-*`.

Перезайти по SSH для группы `incus-admin`, приветствия и Tab. Открыть `e-dev settings`. Новый OUT-интернет закрыт до выбора прямого режима или настройки VPN.

Для ограничений памяти Incus нужен memory cgroup. Установщик сохраняет исходный `cmdline.txt` и при необходимости добавляет `cgroup_enable=memory`. Если он сообщает о необходимости перезагрузки, выполните `sudo reboot`: после неё в `/sys/fs/cgroup/cgroup.controllers` должно появиться `memory`.

### Первый VPN

Экспортировать **клиентский AmneziaWG `.conf`**, а не ссылку приложения Amnezia VPN. Скопировать на Pi вне репозитория, заменив `USER` и `IP_PI`:

```bash
scp ~/Downloads/main.conf USER@IP_PI:~/main.conf
```

На Pi: **Settings → VPN → Конфигурации → Импортировать**. В выборе файла можно вставить путь, дополнить его Tab или пройти по каталогам стрелками/Enter. Файл выбирается на **Pi**, не на Mac. Затем задать имя профиля. Для быстрого импорта также доступно:

```bash
e-dev vpn add main ~/main.conf
```

Выбрать основной/резервный в **VPN → Выбор сервера → DEFAULT**, включить **VPN → Туннель**, затем выбрать **AP → Режим трафика → HYBRID** или **VPN ON**. Исходные копии можно удалить: рабочие ключи находятся в root-only `/etc/e-dev/profiles`. Имена серверов не зашиты. Конфиги с исполняемыми Pre/PostUp/Down и SaveConfig не принимаются.

## Маршрутизация и автономность

- **VPN ON:** весь OUT-интернет через общий VPN; **VPN OFF:** через провайдера, AP продолжает работать; **HYBRID:** российские IP и свои исключения напрямую, остальное VPN.
- **DEFAULT:** после трёх неудачных минутных проверок перейти на доступный резерв; проверять возврат основного раз в 15 минут.
- **MANUAL:** один профиль без автоматической смены.
- **AUTO:** ежедневный Ookla Speedtest в 04:15 по часовому поясу Pi, выбор по download и ping. Сохраняется рейтинг; при потере связи используется доступный профиль. Полный тест расходует сотни MB на профиль.
- **IN-резервирование** настроено отдельно от VPN: разрешённые физические входы, проверки доступности, три неудачи до перехода и три успеха до возврата. Балансировки нагрузки нет.

При потере VPN его трафик не переходит напрямую. Сам Pi и контейнеры `default` используют провайдера; профиль `vpn` использует общий туннель и выбор сервера. HYBRID-исключения только для OUT. При выключенном VPN DNS в HYBRID недоступен; для обычного интернета выбрать VPN OFF.

Hybrid Settings находится в AP: локальная RU-база IPdeny, автообновление, прямые домены/IP и проверка маршрута. Сбой загрузки сохраняет рабочий кэш. DoH/Private Relay обходят доменные правила, но IP-классификация продолжает работать. Общие CDN могут потребовать дополнительных исключений.

Сетевые настройки применяют отдельные systemd-службы даже при потере SSH. При ошибке — откат; при неудачном откате OUT закрыт. Радио AP обновляется с WPA2/RSN/AES-CCMP. Пароли сохраняются в root-only NetworkManager keyfiles, не в аргументах процесса. Дополнительные адаптеры привязаны к постоянным MAC.

## Дашборд, панели и файлы

Дашборд показывает CPU 0–3, CPU all, RAM/swap, историю загрузки и зоны IN/OUT/туннель с общими шкалами RX/TX и графиками интерфейсов. Масштаб сети автоматически следует недавним пикам, это не процент скорости порта. `q` выход, `l` ссылки, `r` обновить, `p` пауза бегущей строки, ↑↓/PgUp/PgDn прокрутка сети. Обновление 2 с; дополнительные сведения служб раз в 10 с.

`e-dev links` читает актуальные IP интерфейсов без mDNS:

| Сервис | Ссылка и вход |
|---|---|
| LXConsole | `https://<IP-Pi>:9443/`, выбранный пользователь и пароль |
| Incus UI | `https://<IP-Pi>:8443/ui/`, клиентский сертификат |
| SMB | `smb://<IP-Pi>/Share`, выбранный пользователь и пароль |

Обе панели управляют одним Incus. В Setup Incus UI создать сертификат, скачать `.crt` и `.pfx`. Передать на Pi только публичный `.crt`, добавить в **Доступ → Incus UI → Доверенные сертификаты**. Приватный `.pfx` импортировать в браузер/связку ключей macOS согласно инструкции Setup. При запросе выбрать клиентский сертификат, а не сервер/root. Сертификат LXConsole защищён от удаления через меню.

Отключение внешнего Incus UI оставляет локальный API для LXConsole. Выключение доступа не останавливает контейнеры/AP/VPN. Выключение SSH запрещает новые подключения; включить снова можно с локальной консоли. Общая смена паролей последовательная: при сбое уже выполненные шаги сохраняются.

Mac: Finder → Подключение к серверу; iOS: Файлы → Подключиться к серверу. Файлы лежат в `/srv/share` на microSD; это временный обмен, единственную копию важных фото хранить отдельно.

## Контейнеры и перенос разработки

```bash
incus launch images:debian/13 demo --profile default
incus launch images:debian/13 demo-vpn --profile vpn
incus exec demo -- bash
```

Профили по умолчанию: 1 GiB RAM, 2 CPU, storage `dir`. Git переносит между ARM Pi и x86 Proxmox исходники и инструкции; на другой архитектуре создать LXC и заново собрать зависимости. ARM rootfs/бинарники не становятся x86 через Git, сетевые профили Incus не переносятся автоматически в PVE.

## Обновление и проверка

```bash
git pull --ff-only
sudo ./update.sh
bash scripts/check.sh
```

Обновление копирует публичный код, меню, документацию и units, не перезаписывает VPN-ключи/пароли и режимы. Конфиги и root-only снимки находятся на Pi, не в Git. Удаляются прежние установленные главы Wi-Fi/паролей, заменённые AP/Доступом.

Журнал сохраняется до 7 дней с лимитом 64 MiB на диске/16 MiB в RAM. Предыдущая загрузка: `sudo journalctl -b -1`; применение: units `e-dev-lan-apply`, `e-dev-wifi-apply`, VPN `e-dev-vpn`, `e-dev-vpn-health`, `e-dev-auto`. Дополнительные USB-переходы, доступ конкретных приложений и питание проверяются на реальном оборудовании отдельно от тестов кода.
