# E-DEV · Raspberry Pi 5

Домашний dev-сервер на Raspberry Pi OS Lite: Wi-Fi-точка доступа с AmneziaWG 3, системные контейнеры Incus, две панели управления, SMB-файлообмен и команда `e-dev`. Система работает самостоятельно: скрипты, systemd и локальные настройки; Mac и нейросеть после установки не нужны.

**Целевая система:** Raspberry Pi 5, Raspberry Pi OS Lite **64-bit**, Debian **13 / trixie**, минимум 4 GiB RAM. Для первой установки подключите Pi к роутеру кабелем. Встроенный `wlan0` используется для AP, `eth0` — для интернета. USB Wi-Fi можно добавить позже.

## Что получится

| Компонент | Назначение |
|---|---|
| Wi-Fi `E-DEV` | WPA2 / RSN / AES-CCMP, DHCP, начальный адрес Pi `10.42.0.1` |
| AmneziaWG 3 | Общий туннель для AP и контейнеров профиля `vpn` |
| Incus | LXC-контейнеры; профиль `default` напрямую, `vpn` через VPN |
| Incus UI | `https://<IP-Pi>:8443/ui/`, вход по клиентскому сертификату |
| LXConsole | `https://<IP-Pi>:9443/`, вход по логину и паролю |
| Samba | `smb://<IP-Pi>/Share`, каталог `/srv/share` |
| `e-dev status` | Живой терминальный дашборд CPU, RAM, сети и режимов |
| `e-dev help`, `man e-dev` | Локальный справочник и Tab-дополнение |

Обе панели управляют **одним** Incus и общими контейнерами. Сам Pi и контейнеры `default` выходят через провайдера. Интернет контейнеров `vpn` остаётся закрытым, если туннель недоступен.

`e-dev links` и страница ссылок в дашборде показывают текущие IPv4 физических LAN/AP-интерфейсов. Адреса берутся из системы, без mDNS и сохранённого IP роутера.

## Установка на новую Pi

1. Запишите Raspberry Pi OS Lite 64-bit через Raspberry Pi Imager. Включите SSH, создайте обычного пользователя с доступом к `sudo`; для привычных примеров можно назвать его `user`. Подключите питание, охлаждение и Ethernet.
2. Войдите по SSH. Узнать адрес можно в DHCP-клиентах роутера.
3. Установите Git и скачайте проект:

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/Egor-Zvada/E-DEV-pi5.git
cd E-DEV-pi5
sudo ./install.sh --country RU
```

`--country` должна соответствовать стране использования Wi-Fi. Можно задать `--user USER --hostname E-DEV --ssid E-DEV --timezone Asia/Sakhalin`. Без `--user` берётся пользователь, запустивший `sudo`.

Установщик проверяет модель, архитектуру, Ethernet и отсутствие пересечения LAN с внутренними подсетями. Затем ставит пакеты, собирает AWG из закреплённых исходников, создаёт Incus, панели и шару. В конце **скрыто запрашивает общий пароль** для SSH, SMB, LXConsole и AP: 8–63 печатных ASCII-символа. В аргументы процесса установщика пароль не передаётся. В репозитории нет пароля по умолчанию.

В первый раз процесс занимает время на загрузку пакетов, Go toolchain и сборку. Установщик предназначен для чистой Pi OS: он откажется менять уже настроенный E-DEV или Incus с данными. При прерванном первичном bootstrap его можно запустить повторно. Предыдущие системные файлы сохраняются в `/opt/e-dev/backups/install-*`.

Перезайдите в SSH после установки: применятся группа `incus-admin`, приветствие и Tab. Интернет новой AP сначала закрыт: нужно импортировать VPN либо явно выбрать прямой выход.

### Добавление VPN-конфигов

Экспортируйте из Amnezia **клиентские `.conf` для AmneziaWG**. Ссылка/ключ приложения Amnezia VPN вместо `.conf` не подходит. Копируйте их в домашний каталог Pi, **вне Git-репозитория**:

```bash
# На Mac; замените USER, путь и имя файла своими значениями.
scp ~/Downloads/main.conf USER@E-DEV.local:~/main.conf
scp ~/Downloads/backup.conf USER@E-DEV.local:~/backup.conf
```

На Pi:

```bash
e-dev vpn add main ~/main.conf
e-dev vpn add backup ~/backup.conf
e-dev vpn settings default       # выбрать основной и резервный по номерам
e-dev vpn on
e-dev wifi hybrid
e-dev wifi status
```

Названия произвольные; серверы не зашиты в код и справочник. После импорта можно удалить исходные копии из домашнего каталога: рабочие конфиги находятся в `/etc/e-dev/profiles`, доступны только root. Конфиги с исполняемыми `PreUp`/`PostUp`/`PreDown`/`PostDown` не принимаются. Runtime убирает DNS/маршруты из входного конфига и применяет свою маршрутизацию.

## Wi-Fi и VPN — отдельные настройки

| Команда | Результат |
|---|---|
| `e-dev wifi status` | Состояние AP, режим трафика, выбранный сервер, режим выбора VPN |
| `e-dev wifi vpn on` | Интернет AP через VPN |
| `e-dev wifi vpn off` | Интернет AP напрямую через провайдера; **AP остаётся включённой** |
| `e-dev wifi hybrid` | Российские сети и исключения напрямую, остальное через VPN |
| `e-dev wifi mode` | Интерактивный выбор этих трёх маршрутов |
| `e-dev vpn on` / `off` | Запуск / остановка самого туннеля |

Также доступны `e-dev wifi mode vpn|direct|hybrid`. Старые `wifi on/off` и `wvpn` оставлены как совместимые алиасы; новые подсказки используют названия выше.

AP-маршрут и состояние туннеля сохраняются. Если выключить сам VPN, трафик VPN-контейнеров и VPN-часть AP не перейдёт к провайдеру. В HYBRID прямые IP-исключения могут работать, но его DNS использует туннель. Для обычного интернета без VPN используйте `e-dev wifi vpn off`.

### Выбор VPN-сервера

- `e-dev vpn settings default`: выбрать основной и резервный. После трёх неудачных проверок основной заменяется доступным резервным; возврат проверяется раз в 15 минут.
- `e-dev vpn default`: применить сохранённый основной/резерв. Без меню: `e-dev vpn default main backup`.
- `e-dev vpn manual`: выбрать единственный сервер; автоматического переключения нет. Без меню: `e-dev vpn manual main`.
- `e-dev vpn auto`: измерить профили официальным Ookla Speedtest CLI и выбрать лучший по download, при равенстве — меньшему ping. В Auto ежедневный замер запускает systemd в 04:15 по часовому поясу Pi; повторный вход в Auto в тот же день использует рейтинг. При падении выбранного сервера используется доступный из рейтинга.
- `e-dev speedtest`: замерить **активный** VPN, сохранив режим и выбранный сервер.
- `e-dev vpn auto run`: принудительно повторить полный рейтинг; `e-dev vpn speeds`: посмотреть результаты.
- `e-dev vpn list`, `add NAME FILE`, `remove NAME`, `rename OLD NEW`, `status`: управление конфигами и диагностика.

Auto и Default работают автономно. В выключенном VPN они не запускают туннель обратно. Speedtest расходует заметный трафик; Auto измеряет каждый профиль. CLI вызывает Ookla с `--accept-license --accept-gdpr`; условия сервиса доступны на [странице Ookla](https://www.speedtest.net/apps/cli).

### Настройки гибрида

```bash
e-dev wifi hybrid settings
e-dev wifi hybrid settings domains add example.ru
e-dev wifi hybrid settings ips add 1.0.0.1/32  # пример: прямой маршрут к одному публичному IP
e-dev wifi update
e-dev wifi check ozon.ru
```

В меню: прямые домены и IPv4/CIDR, DNS, использование и автообновление базы RU. База IPdeny хранится локально, сохраняется при ошибке скачивания и загружается после перезапуска. По умолчанию есть `.ru`, `.su`, `.рф` и вспомогательные домены Ozon, WB, Госуслуг, 2ГИС. По умолчанию DNS — `1.1.1.1`, `8.8.8.8`; для VPN/HYBRID DNS-запросы уходят через туннель.

GeoIP не определяет владельца сервиса безошибочно. CDN и дополнительные домены иногда требуют своего исключения. Правила относятся к **AP**; профиль контейнера `vpn` остаётся целиком VPN. Зашифрованный DNS приложений может обходить доменное наполнение списка; проверка по RU IP-базе при этом остаётся. IPv6 AP и мостов отключён.

## Дашборд, справочник, пароли

```bash
e-dev status              # графики и логотип; q — выход, l — ссылки, p — пауза строки
e-dev status --once       # короткий текст, удобно для логов
e-dev wifi status        # только AP, маршрут и выбранный VPN
e-dev wifi clients       # подключённые клиенты, IP/MAC и радио-скорость
e-dev wifi settings      # меню подсети AP, диапазона и аренды DHCP
e-dev links              # актуальные адреса панелей и SMB
e-dev passwd all         # общий новый пароль SSH / SMB / AP / LXConsole
e-dev help
man e-dev
```

Имена команды: `e-dev`, `E-DEV`, `E-dev`, `edev`. Tab дополняет подкоманды, профили, пути и контейнеры. В дашборде ASCII-логотип адаптируется к ширине окна: компактный от 80 столбцов, полный сбоку от 128 при высоте от 24 строк. 

Вверху цветные шкалы четырёх ядер CPU, RAM и swap, ниже история общей CPU/RAM. Сеть разделена на IN, OUT и туннель: общие шкалы RX/TX и скорость/графики каждого назначенного интерфейса. Графики растут по высоте окна; длинный список прокручивается ↑/↓, PgUp/PgDn, Home/End. В окне ниже 24 строк остаются общие шкалы зон. Нижняя строка плавно движется; `p` ставит её на паузу и продолжает движение, `r` обновляет показатели. Дашборд обновляется каждые 2 секунды; сведения служб — раз в 10 секунд. Счётчик клиентов требует доступа к `iw`: без root/доступного `sudo` он показывает `—`; подробный `wifi clients` сам вызывает `sudo`. 

Шкалы сети показывают Мбит/с с явно указанным автоматическим масштабом по пикам последних 90 отсчётов (примерно 3 минуты), а не процент максимальной скорости линии. RX — принятые Pi байты, TX — отправленные; графики туннеля показывают его собственные счётчики. IN суммирует назначенные физические входы, OUT — физические порты, без повторного добавления счётчиков моста. `*` отмечает активный IN, `R` — резерв. В RAM зелёный сегмент — `MemTotal − MemAvailable`, голубой — доступная часть кеша; значение справа показывает занятый RAM. Значения RAM/swap в GiB. 

Наличие интерфейса в дашборде не подтверждает работающий интернет: для handshake используйте `e-dev vpn status`.

Изменение AP-пароля переподключает клиентов. Incus UI использует клиентский сертификат, поэтому пароль к нему не применяется. `passwd all` меняет сервисы последовательно; если один шаг не выполнен, уже выполненные изменения сохраняются.

Подсеть и DHCP можно менять через меню или команды:

```bash
e-dev wifi settings show
e-dev wifi settings network 192.168.50.1/24
e-dev wifi settings dhcp 192.168.50.100 192.168.50.200
e-dev wifi settings dhcp auto
e-dev wifi settings lease 7200
```

`network` без диапазона выбирает автоматический DHCP-пул; можно передать начало и конец ещё двумя аргументами. Разрешены частные подсети /16–/28 без пересечения с LAN, VPN и сетями контейнеров. `lease 0` возвращает часовую аренду по умолчанию. Применение выполняет служба `e-dev-wifi-apply`: Wi-Fi-клиенты переподключатся, SSH через AP может оборваться, но изменение продолжится. Обновляются маршруты, firewall и DNS; режим AP и выбранный VPN сохраняются. При ошибке служба откатывает настройки, а при неудачном откате оставляет AP-трафик закрытым. Результат: `e-dev wifi settings show` и `journalctl -u e-dev-wifi-apply`. Снимки настроек лежат в `/opt/e-dev/backups/wifi-*`; исправление после неудачного отката выполняйте через Ethernet.

Параметры DHCP использует [NetworkManager](https://networkmanager.dev/docs/api/latest/settings-ipv4.html). Сеть AP хранится в `/etc/e-dev/wifi.json`; текущие адреса для входа всегда смотрите через `e-dev links`.

## Вход в панели

LXConsole: скопируйте ссылку с текущим IP из `e-dev links`, подтвердите локальный самоподписанный TLS-сертификат и войдите Linux-именем, выбранным установщиком, с общим паролем. Панель не требует клиентского сертификата браузера.

Incus UI: откройте ссылку с портом `8443` из `e-dev links`, создайте браузерный сертификат на странице Setup, скачайте `.crt` и `.pfx`. **Публичный `.crt`** передайте на Pi и добавьте в доверенные:

```bash
sudo incus config trust add-certificate /path/to/incus-ui.crt --name="E-DEV browser"
```

`.pfx` импортируйте в браузер либо связку ключей входа macOS согласно вкладке **macOS** в Setup. При запросе выбирайте созданный клиентский сертификат, а не сертификат сервера/root. После импорта перезапустите браузер, если он сохранил старый выбор. Приватный `.pfx` не передавайте на Pi/GitHub. На каждом новом клиентском устройстве можно создать отдельный сертификат.

## Контейнеры и файлы

```bash
incus launch images:debian/13 demo --profile default
incus launch images:debian/13 demo-vpn --profile vpn
incus exec demo -- bash
```

Профили по умолчанию ограничены 1 GiB RAM и 2 CPU. Storage — `dir`, экономный вариант для microSD. Профиль `vpn` использует тот же сервер и Default/Manual/Auto, что AP; переключение AP на DIRECT не меняет маршрут VPN-контейнеров. Для добавления опубликованного порта используйте proxy device Incus или адрес самого контейнера в маршрутизируемой сети.

Git переносит между ARM Pi и x86 PVE **исходники и инструкции сборки**. На работе создавайте x86 LXC и заново устанавливайте зависимости/собирайте проект. ARM rootfs или скомпилированные ARM-бинарники не становятся x86 через Git. Сетевой профиль Incus не переносится автоматически в сетевые настройки PVE.

На Mac: Finder → «Перейти» → «Подключение к серверу» → SMB-ссылка с IP из `e-dev links`. На iOS: «Файлы» → меню → «Подключиться к серверу», текущий IP Pi со стороны AP или LAN. Вход выбранным пользователем и паролем. Данные лежат на microSD в `/srv/share`; это временный файлообмен, единственную копию фото храните отдельно.

## Сеть IN / OUT и резервный интернет

```bash
e-dev lan setup       # стрелки, Enter, Space в списке резервов, Esc назад
e-dev lan status
e-dev lan check
```

Псевдографическое меню открывается в SSH или на локальном мониторе (минимум 60×20). **IN** содержит источники интернета; **OUT** — порты общей клиентской сети. `eth0` закреплён в IN, встроенный `wlan0` — в OUT. Меню обнаруживает USB Ethernet/Wi-Fi; назначение привязано к постоянному MAC, поэтому смена USB-порта не меняет роль.

Для Wi-Fi донгла: IN → Добавить → адаптер → SSID/защита/пароль → DHCP или статика/шлюз/DNS. Донгл подключится заранее, но его отдельная таблица маршрутов не заменит основной интернет. Затем в «Основной / резервные / автопереход» выберите основной, отметьте резервы, их порядок и включите автопереход. По умолчанию основной — `eth0`, резервов нет, автопереход выключен. Если автопереход выключен, резерв не используется. Это переключение между входами, балансировки трафика нет.

Служба проверяет реальный доступ к HTTPS через каждый разрешённый вход примерно каждые 20–30 секунд. После трёх неудач выбирает доступный резерв; при исчезновении активного устройства — сразу. Возвращается на основной после трёх успешных проверок. Если разрешённые входы недоступны, случайный подключённый интерфейс не становится выходом. Выбор VPN и режим OUT сохраняются; туннель переподключается при смене входа. Mac и AI для работы не нужны.

Для USB сетевухи с клиентом: OUT → Добавить → адаптер. Общий мост `edevbr0` объединяет AP и проводные OUT-порты: одна подсеть, DHCP-пул и режим VPN ON/OFF/HYBRID. IP теперь находится на мосту, а `wlan0` остаётся радио. Дополнительный Wi-Fi в OUT работает точкой доступа с унаследованными настройками AP, если драйвер поддерживает AP; Wi-Fi в IN работает клиентом. Подсеть и DHCP меняются через пункт меню OUT или `e-dev wifi settings`. Панели и SMB доступны по текущим IP из `e-dev links`.

Изменения подтверждаются перед применением. Отдельная служба `e-dev-lan-apply` продолжит работу при разрыве SSH; при ошибке восстановит снимок. Откат проверяет прежние подключения и адрес OUT; если восстановление не подтверждено, трафик OUT закрыт. Для исправления используйте Ethernet или локальную консоль. Снимки `/opt/e-dev/backups/lan-*` содержат пароли и доступны только root. Wi-Fi IN пароль не попадает в публичную конфигурацию `/etc/e-dev/lan.json` или аргументы команд.

На существующей установке без LAN-конфигурации первое открытие `lan setup` предложит перенос AP на мост; `update.sh` устанавливает код, но сам не меняет роли. На свежей установке мост создаётся установщиком. Дополнительные USB-адаптеры и реальный переход между ними требуют проверки после подключения оборудования. Параметры сети использует [NetworkManager](https://networkmanager.dev/docs/api/latest/settings-ipv4.html).

## Обновление и восстановление

На уже настроенной Pi обновляйте только код:

```bash
git pull --ff-only
sudo ./update.sh
```

`update.sh` сохраняет конфиги, режимы, пароли, LXConsole DB, контейнеры и `/srv/share`. Делает root-only копию предыдущего кода, служб, справочника и `/etc/e-dev` в `/opt/e-dev/backups/code-*`, затем обновляет собственные компоненты E-DEV. Туннель переподключается; пакеты AWG/Incus/LXConsole этим скриптом не обновляются. Полный `install.sh` поверх работающей системы не запускайте.

Перед переносом/перезаписью карты сохраните отдельно: `/etc/e-dev`, `/etc/NetworkManager/system-connections`, `/opt/lxconsole/{.env,instance,certs,tls}`, `/srv/share`, данные или экспорты Incus. Эти копии содержат секреты и **не предназначены для GitHub**. Для согласованной копии LXConsole остановите его на время копирования DB; контейнеры экспортируйте через `incus export NAME /path/NAME.tar.gz` или штатный snapshot/backup. На другой Pi лучше создать новые сертификаты UI и импортировать VPN-профили заново.

Откат кода из `code-*`: восстановите `bin/e-dev` в `/usr/local/bin`, `sbin/e-dev-*` в `/usr/local/sbin`, `units/*` в `/etc/systemd/system`, `docs` в `/opt/e-dev/docs`, `completion` и `e-dev.1` в соответствующие каталоги. Исполняемым файлам задайте `755`. Затем `sudo systemctl daemon-reload` и `sudo /usr/local/sbin/e-dev-vpn boot`. Восстановление `config` в `/etc/e-dev` требуется только для отката настроек; не подменяйте свежие ключи случайно.

## Исходники и проверки

- `src/`: CLI, дашборд, маршрутизация, AWG lifecycle, выбор VPN, гибрид и GeoIP.
- `config/systemd/`: службы и таймеры; `config/versions.env`: закреплённые AWG/LXConsole revisions и checksum Speedtest.
- `scripts/bootstrap.py`, `bootstrap_lxconsole.py`: начальная настройка без готовых личных конфигов.
- `scripts/build_wiki.py`: генерирует `docs/COMMANDS.md`, `docs/wiki`, man-страницу; `assets/`: ASCII-логотип и Bash completion.
- `tests/`, `.github/workflows/checks.yml`: проверки выбора сервера, защиты маршрутов, новых команд и размеров дашборда.

```bash
bash scripts/check.sh
# На Pi/Linux: изолированная проверка маршрутов ядра
sudo python3 tests/integration_network.py
```

Рабочая система проверена на Pi 5 / Debian 13 ARM64: смена серверов, отказ основного/возврат, Auto, блокировка VPN-трафика при выключенном туннеле, гибрид, контейнер VPN и мягкая перезагрузка. Проверены правила `nft`, systemd units, новая база LXConsole и вход в неё. Полный установщик на **второй чистой физической Pi/карте пока не прогонялся**; проверки CI не заменяют проверку Wi-Fi/аппаратной сети. Реальный ARM ↔ x86 перенос приложения и обновление Meta-очков отдельно не подтверждены.

APT-пакеты берутся из Debian/Pi OS и подписанного репозитория Zabbly LTS 6.0; их patch-версии могут меняться. Это воспроизводимая схема настройки с закреплёнными исходниками AWG/LXConsole, а не побитовая копия ОС.
