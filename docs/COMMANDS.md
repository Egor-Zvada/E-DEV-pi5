```text

Egor Zvada • E-DEV • egor-zvada.ru

  e-dev settings          настройки LAN, OUT, AP, VPN и доступа
  e-dev status            живой дашборд
```

## НАЧАЛО И УПРАВЛЕНИЕ

```text
НАЧАЛО И УПРАВЛЕНИЕ

Настройки: e-dev settings. В SSH и на локальной консоли одно меню:
  LAN / IN        источники интернета и резервирование
  OUT             дополнительные порты сети клиентов
  AP              Wi-Fi, подсеть, DHCP, DNS, режим трафика и Hybrid Settings
  VPN             туннель, профили, выбор сервера и измерения
  Статус          живой дашборд; q возвращает в Settings
  Доступ и пароли  SSH, панели, файлы, сертификаты и общий пароль

Стрелки — выбор; Enter — открыть; Space — отметить резервные входы.
Esc / Назад — вернуться. Изменение выполняется после завершения выбора;
отмена незавершённого выбора не меняет настройки. Сетевые изменения
подтверждаются перед применением. Меню требует терминал минимум 60×20.

Все изменяемые настройки находятся в Settings. Старые публичные команды
wifi settings, lan setup, vpn on/off, vpn manual/auto и подобные убраны.
Прямой импорт e-dev vpn add NAME FILE сохранён в главе VPN.

e-dev manuals открывает выбор глав. В тексте: стрелки / PgUp / PgDn,
/ поиск, q — обратно к списку. e-dev help показывает короткий список.
Tab в оболочке дополняет актуальные команды. Имена: e-dev, E-DEV, E-dev, edev.
В SSH-сессии, открытой до версии 1.0, один раз выполнить:
  source /etc/bash_completion.d/e-dev
Либо перезайти по SSH. После этого Tab сам подхватывает обновления команд.
Логотип в Settings меняет размер вместе с окном, сохраняя рамку.
При возврате остаётся выбранный пункт; Esc возвращает на уровень выше.

Дашборд: CPU 0–3 и CPU all, RAM/swap, истории CPU/RAM; зоны IN, OUT
и туннель, общие шкалы RX/TX и графики каждого интерфейса.
RX — принятые Pi байты, TX — отправленные. Сетевые шкалы в Мбит/с
с автоматическим масштабом по недавним пикам, не процент скорости порта.
q — выход, l — ссылки, r — обновить, p — пауза бегущей строки.
При большом числе портов ↑↓ / PgUp / PgDn прокручивают сетевую область.
В маленьком окне остаётся общая CPU и шкалы зон. Обновление каждые 2 с.

Ссылки читаются из текущих IPv4 интерфейсов, без mDNS и сохранённого IP.
Все режимы, таймеры и проверки выполняются на Pi. Mac и AI не нужны.
```

## LAN / IN — ВХОДЫ ИНТЕРНЕТА

```text
LAN / IN — ВХОДЫ ИНТЕРНЕТА

e-dev settings → LAN / IN

«Входы интернета»: открыть интерфейс, посмотреть адреса и роль;
выбрать DHCP или статический IPv4/маску, шлюз и DNS.
Для USB Wi-Fi здесь выбирается SSID и скрыто вводится пароль сети.
Новый адаптер сначала нужно добавить из списка обнаруженных устройств.
eth0 закреплён в IN. Роли USB-портов привязаны к постоянным MAC.

«Основной / резервы / автопереход»: выбрать основной вход,
Space отметить резервные, задать порядок и включить автопереход.
Подключённый заранее вход не используется глобально, пока не выбран
основным или разрешённым резервом. Его маршрутизация изолирована.
По умолчанию резервы отсутствуют, автоматическое переключение выключено.

HTTPS-проверки выполняются через каждый разрешённый вход. Три неудачи
подряд — переход на доступный резерв; физическое исчезновение — сразу.
Возврат на основной после трёх успешных проверок. Интервал около 20–30 с,
зависит от количества входов и таймаутов. Балансировки нагрузки нет.
Неизвестный вход при потере всех настроенных автоматически не подключается.

«Проверить входы сейчас» запускает проверку; «Состояние LAN» показывает роли.
Команда без меню: e-dev lan status.
При смене входа VPN переподключается; выбранный профиль и режим сохраняются.

Применение выполняет systemd-служба независимо от SSH, при ошибке — откат.
После неудачного отката OUT-трафик закрыт; восстановить с Ethernet или
монитора/клавиатуры. Журнал: journalctl -u e-dev-lan-apply -u e-dev-uplink.
USB-драйвер должен поддерживаться Pi OS; реальный резерв проверяется
после подключения оборудования. Пароли IN хранятся в root-only keyfiles.
```

## OUT — ДОПОЛНИТЕЛЬНЫЕ ПОРТЫ

```text
OUT — ДОПОЛНИТЕЛЬНЫЕ ПОРТЫ

e-dev settings → OUT

Встроенный wlan0 закреплён в OUT. Здесь добавляются обнаруженные
USB Ethernet и Wi-Fi AP-адаптеры; ненужный внешний порт можно освободить.
Внешний Wi-Fi в OUT работает точкой, драйвер должен поддерживать AP.
Клиентский Wi-Fi для получения интернета настраивается в LAN / IN.
Один физический интерфейс может принадлежать только одной зоне.

OUT — общий мост edevbr0. IP и DHCP находятся на мосту; порты сами
не получают отдельные IP. Проводные клиенты и AP получают адреса из
одного пула, имеют доступ к панелям и файлам, используют один режим
VPN ON / VPN OFF / HYBRID. Счётчики моста не удваивают сетевые графики.

Подсеть, DHCP, DNS и режим трафика настраиваются только в разделе AP.
Роли привязаны к MAC: смена USB-порта или имени устройства их не меняет.
Изменение состава OUT подтверждается; служба выполняет откат при ошибке.
```

## AP — WI-FI, DHCP И DNS

```text
AP — WI-FI, DHCP И DNS

e-dev settings → AP

«Wi-Fi»: название сети, диапазон 2.4/5 GHz, канал и пароль точки.
Канал 0 — автоматически; доступность зависит от драйвера и страны Wi-Fi.
Защита WPA2 / RSN / AES-CCMP, без WPA/TKIP. Настройки Wi-Fi применяются
ко всем Wi-Fi AP-портам OUT. Изменение переподключает клиентов.

«Подсеть и DHCP»: IPv4 Pi с маской, диапазон выдачи и срок аренды.
Частные сети /16–/28 без пересечения с IN, VPN и контейнерами.
При смене подсети пул становится автоматическим; можно задать свой.
Адрес Pi не может попасть в пул. Аренда 0 = час по умолчанию,
остальные значения от 120 до 31536000 секунд.
Подсеть и DHCP общие для всей OUT-сети, включая проводные порты.

«DNS»: от одного до трёх публичных IPv4, начальные 1.1.1.1 и 8.8.8.8.
В VPN/HYBRID DNS идёт через awg0, в VPN OFF — через провайдера.
Для прямого режима новые DNS применяются при следующей активации OUT.

«Режим трафика»:
  VPN ON   весь интернет OUT через общий туннель
  VPN OFF  весь интернет OUT через провайдера
  HYBRID   российские IP и прямые исключения — провайдер, остальное VPN
Точка остаётся включённой. Режим трафика не запускает и не останавливает
сам VPN; это делается в Settings → VPN → Туннель.
Если туннель выключен, VPN-выход закрыт. Для интернета без VPN выберите
VPN OFF. Настройки Hybrid Settings не включают HYBRID автоматически.

Команды просмотра: e-dev wifi status, e-dev wifi clients.
Старые DHCP-записи показываются отдельно и не входят в счётчик клиентов.
Радио-скорость iw не равна скорости интернета. IPv6 в OUT отключён.
Если iPhone помнит предупреждение о WPA, забыть сеть и подключиться снова.

Подсеть/радио применяет отдельная служба, даже при разрыве SSH.
При ошибке — откат; при ошибке отката AP-трафик остаётся закрытым.
Режим AP и профиль VPN сохраняются. Результат: e-dev wifi status;
журнал: journalctl -u e-dev-wifi-apply. Текущие адреса: e-dev links.
```

## HYBRID — ПРЯМЫЕ ИСКЛЮЧЕНИЯ

```text
HYBRID — ПРЯМЫЕ ИСКЛЮЧЕНИЯ

e-dev settings → AP → Hybrid Settings

«Учёт RU IP-базы»: использовать российские IPv4-сети IPdeny.
«Ежедневное обновление»: скачивать базу автоматически.
«Обновить IP-базу сейчас»: загрузить вручную.
Последний рабочий кэш остаётся локально, при сбое загрузки не удаляется.
Без интернета классификация продолжает работать с сохранённой базой.

«Прямые домены»: добавить/удалить домен без https:// и пути;
правило включает поддомены. Начальные исключения включают .ru/.su/.рф
и вспомогательные домены Ozon, Wildberries, Госуслуг и 2ГИС.
«Прямые IP / сети»: публичный IPv4 или CIDR не шире /8.
«Проверить маршрут»: ввести домен/IP, увидеть IPv4, маршрут и причину.
Это проверка выбора маршрута, не доступности приложения.

При выключенном учёте RU-базы свои доменные/IP-правила остаются.
Все остальные назначения в HYBRID направляются через VPN.
Изменения применяются сразу; старые соединения могут требовать
переподключения. DNS задаётся в AP → DNS и общий для режимов точки.
TCP/UDP 53 перехватывается Pi. DoH/Private Relay обходят доменные
правила, но классификация по RU IP-базе и своим IP продолжает действовать.

Общие CDN-IP могут обслуживать разные сайты; зарубежные CDN российских
сервисов иногда требуют дополнительных исключений. Проверяйте адреса
конкретного сервиса. VPN-контейнеры идут целиком через общий туннель,
исключения HYBRID действуют только для OUT. Выбор VPN-сервера здесь
не меняется. В HYBRID при выключенном VPN DNS через туннель недоступен.
```

## VPN — ТУННЕЛЬ, ПРОФИЛИ И ВЫБОР СЕРВЕРА

```text
VPN — ТУННЕЛЬ, ПРОФИЛИ И ВЫБОР СЕРВЕРА

e-dev settings → VPN

«Туннель»: включить/выключить сам AmneziaWG. Состояние сохраняется.
Выбор профиля при выключенном VPN не включает туннель.
«Состояние туннеля»: профиль, режим выбора, handshake и счётчики.
Команда без меню: e-dev vpn status.

«Выбор сервера»:
  DEFAULT — выбрать основной, затем резервный или «Без резерва».
  MANUAL  — выбрать один профиль, автоматических переключений нет.
  AUTO    — автономный ежедневный выбор по измеренной скорости.

DEFAULT: после трёх неудачных минутных проверок переключается
на доступный резерв. На резерве основной проверяется раз в 15 минут.
После включения/перезагрузки начинается с основного.
MANUAL: при недоступности выбранного сервера VPN-интернет закрыт
до его восстановления или ручной смены. Роли DEFAULT сохраняются.
AUTO: Ookla измеряет download/upload/ping каждого импортированного
профиля; побеждает download, при равенстве меньший ping. Текущий туннель
во время теста другого профиля сохраняется. Ежедневный тест в 04:15
по часовому поясу Pi с небольшим случайным сдвигом; один раз в день.
Повторный вход в AUTO использует сегодняшний рейтинг. При обрыве
выбирается доступный из рейтинга. Если все тесты не удались, текущий
выбор сохраняется. При выключенном туннеле тесты AUTO пропускаются.
Скрипты, кэш, проверки и таймеры работают на Pi без AI и Mac.

«Конфигурации»: импортировать полный клиентский .conf AmneziaWG;
открыть профиль для замены, переименования или удаления.
Выбор файла: вставить путь, Tab дополнить, ↑↓ выбрать, Enter открыть
каталог/файл, Esc отменить. Путь относится к файловой системе Pi.
Имя профиля: буквы, цифры, дефис, подчёркивание, до 32 символов.
Имена и роли читаются из текущих конфигов, серверы не зашиты в меню.
Удалить активный, основной или резервный нельзя, сначала смените роли.
Переименование сохраняет роли и рейтинг; замена активного переподключает его.
Конфиги с командами Pre/PostUp/Down и SaveConfig не принимаются.
Ключи /etc/e-dev/profiles доступны только root и не печатаются в меню.

Прямой импорт для быстрого доступа (не показывается в кратком help):
  e-dev vpn add NAME FILE
Например: e-dev vpn add main ~/main.conf
Исходный .conf сначала скопируйте на Pi вне Git-репозитория.
Экспорт приложения Amnezia VPN в виде ссылки не заменяет AWG .conf.

«Измерения»: скорость активного VPN, результаты AUTO, повторить сравнение.
Полный Speedtest расходует сотни MB на профиль и делит канал с клиентами.
Принудительное сравнение доступно в AUTO. Команда e-dev speedtest
измеряет активный VPN, сохраняя выбранный сервер и режим.

Выбор VPN общий для OUT в VPN ON/HYBRID и контейнеров профиля vpn.
Сам Pi и контейнеры default используют провайдера. При потере VPN
его трафик не переключается напрямую. Внешний IP проверяйте на клиенте.
```

## ДОСТУП И ПАРОЛИ

```text
ДОСТУП И ПАРОЛИ

e-dev settings → Доступ и пароли

Открыть SSH, LXConsole или Файлы SMB: включить/выключить доступ,
сменить отдельный пароль. Включение/выключение сохраняется после reboot.
Выключение SSH запрещает новые подключения; снова включить можно
через монитор и клавиатуру. Выключение доступа не останавливает
контейнеры, точку доступа или VPN.

Incus UI: включить/выключить внешний HTTPS-доступ, управлять доверенными
сертификатами. Локальный API на 127.0.0.1:8443 остаётся для LXConsole.
«Доверенные сертификаты»: добавить публичный .crt, отозвать выбранный.
Служебный сертификат LXConsole удалить через меню нельзя.
Для Incus UI пароль не применяется: приватный .pfx хранится у браузера.

«Общий новый пароль»: SSH, LXConsole, SMB и Wi-Fi AP последовательно.
Также доступна команда e-dev passwd all. При ошибке уже выполненные
изменения сохраняются. Новый пароль вводится скрыто дважды:
8–63 печатных ASCII-символа. Он не передаётся через argv или Git.
Применение Wi-Fi завершает отдельная служба, клиенты переподключатся.

«Включить / выключить доступ ко всем сервисам» управляет SSH,
обеими панелями и SMB. Wi-Fi не выключается этим пунктом.
Отдельная смена пароля точки находится только в AP → Wi-Fi.
Текущие адреса и имя пользователя: e-dev links.
```

## ВХОД В ПАНЕЛИ

```text
ВХОД В ПАНЕЛИ

e-dev links показывает текущие IP, без mDNS:
  LXConsole  https://<IP-Pi>:9443/     пользователь + пароль
  Incus UI   https://<IP-Pi>:8443/ui/  клиентский сертификат
Обе панели управляют одним Incus и общими контейнерами.

LXConsole: подтвердить самоподписанный серверный TLS-сертификат,
войти пользователем, выбранным при установке. Пароль меняется
в Settings → Доступ и пароли → LXConsole.

Incus UI: на странице Setup создать браузерный сертификат,
скачать публичный .crt и приватный .pfx. Передать только .crt на Pi;
Settings → Доступ и пароли → Incus UI → Доверенные сертификаты → Добавить.
.pfx импортировать в браузер/связку ключей входа macOS согласно
вкладке macOS в Setup. При запросе выбрать клиентский сертификат,
а не сервер/root. Если браузер запомнил старый выбор, перезапустить его.
Для другого клиентского устройства можно создать отдельный сертификат.
Публичный .crt также можно добавить через incus config trust add-certificate.
Приватный .pfx не передавать на Pi или GitHub.
```

## КОНТЕЙНЕРЫ И ARM / X86

```text
КОНТЕЙНЕРЫ И ARM / X86

Контейнеры управляются через Incus UI, LXConsole или обычный incus CLI:
  incus launch images:debian/13 demo --profile default
  incus launch images:debian/13 demo-vpn --profile vpn
  incus exec demo -- bash

default — интернет через провайдера. vpn — целиком через общий VPN;
выбранный в Settings профиль и DEFAULT/MANUAL/AUTO общие с AP.
HYBRID действует только на OUT, VPN-контейнеры без прямых исключений.
Профили по умолчанию: 1 GiB RAM и 2 CPU, storage dir для microSD.
Публикация портов: proxy device Incus или маршрутизация к IP контейнера.

Git переносит исходники и инструкции сборки между ARM Pi и x86 PVE.
На другой архитектуре создать LXC и заново собрать/установить зависимости.
ARM rootfs и ARM-бинарники не становятся x86 через Git.
Сетевые профили Incus не переносятся автоматически в Proxmox.
```

## ФАЙЛЫ С MAC / IPHONE

```text
ФАЙЛЫ С MAC / IPHONE

e-dev links → SMB-ссылка с текущим IP.
Mac: Finder → Перейти → Подключение к серверу → smb://<IP-Pi>/Share.
iOS: Файлы → меню → Подключиться к серверу → текущий IP Pi.
Пользователь выбран при установке, пароль SMB меняется в
Settings → Доступ и пароли → Файлы SMB.

Каталог на Pi: /srv/share. Это временный обмен фото/видео и файлами;
единственную копию важных фотографий храните отдельно от microSD.
Доступен из IN/OUT по IP, если доступ SMB включён.
```

## ДИАГНОСТИКА

```text
ДИАГНОСТИКА

  e-dev status --once
  e-dev lan status
  e-dev wifi status
  e-dev wifi clients
  e-dev vpn status
  e-dev links

Нет VPN-интернета: Settings → VPN → Состояние туннеля.
Интерфейс awg0 не подтверждает связь; нужен свежий handshake.
MANUAL сам не переключается; другой профиль выбрать в VPN → Выбор сервера.

Неудачный Speedtest: VPN → Измерения → Последние результаты AUTO;
журнал e-dev-auto. Ошибка теста не включает прямой выход для VPN.
После смены AP-пароля/SSID подключить клиентов с новыми настройками.
После смены подсети смотреть e-dev links; старые IP-ссылки перестают работать.

Журналы:
  sudo journalctl -u e-dev-vpn -u e-dev-dns -u e-dev-vpn-health -n 80
  sudo journalctl -u e-dev-lan-apply -u e-dev-network -u e-dev-uplink -n 80
  sudo journalctl -u e-dev-wifi-apply -u e-dev-auto -n 80

лимит 64 MiB на диске и 16 MiB в RAM. Питание: vcgencmd get_throttled.
```
