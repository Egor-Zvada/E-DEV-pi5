## vpn

```text
ТУННЕЛЬ И ОБЩИЙ ВЫБОР VPN-СЕРВЕРА

  e-dev vpn status                  туннель, handshake, текущий режим выбора
  e-dev vpn on|off                   включить/выключить сам туннель
  e-dev vpn list                     текущие профили; * — выбранный
  e-dev vpn settings                 интерактивное меню режимов
  e-dev vpn settings default         спросить основной, затем резервный
  e-dev vpn default                  включить сохранённый основной/резерв
  e-dev vpn default MAIN RESERVE     основной + резерв без меню
  e-dev vpn default MAIN -           основной без резерва
  e-dev vpn manual                   пронумерованное меню одного профиля
  e-dev vpn manual NAME              только этот профиль, без переключений
  e-dev vpn use NAME                 короткий вариант manual NAME
  e-dev vpn auto                     Auto: измерить и выбрать самый быстрый
  e-dev vpn auto run                 повторить замер сейчас (режим Auto)
  e-dev vpn speeds                   последние результаты Auto
  e-dev vpn selection                режим, роли и результаты Auto
  e-dev speedtest                    Ookla через активный VPN, выбор сохраняется
  e-dev vpn speedtest                то же самое

DEFAULT: основной и резерв выбираются из актуального списка ключей.
Раз в минуту проверяется доступ в интернет через туннель. После трёх
неудачных проверок выбирается доступный резерв. На резерве основной
проверяется раз в 15 минут; при восстановлении Pi возвращается на него.
Проверки не включают прямой выход. Без рабочего VPN VPN-трафик закрыт.
После включения/перезагрузки Default начинает с основного сервера.

MANUAL: один выбранный профиль. Автоматических переключений нет.
Если сервер недоступен, интернет через VPN не работает до восстановления
или ручной смены. Настройки основного и резерва сохраняются для Default.

AUTO: официальный Ookla Speedtest замеряет download/upload/ping через
каждый импортированный профиль. Побеждает больший download; при равенстве
меньший ping. Во время проверки другого профиля текущий туннель сохраняется.
Тесты делят общую пропускную способность Ethernet и расходуют трафик:
полный тест может потреблять сотни MB на профиль. По расписанию тест
в 04:15 по часовому поясу системы (с небольшим случайным сдвигом), максимум раз в день.
При первом Auto без сегодняшнего рейтинга — немедленный замер.
Повторный Auto в тот же день использует рейтинг и проверяет доступность.
auto run делает новый замер принудительно. Результат зависит от нагрузки
в момент теста и выбранного сервером Speedtest узла.
Если все замеры не удались, текущий выбор сохраняется. При обрыве текущего
сервера проверка связи выбирает доступный из последнего рейтинга, затем
из оставшихся профилей. Следующий успешный замер обновит рейтинг.
Вся логика, таймеры, кэш и проверки находятся на Pi; AI и Mac не нужны.

  e-dev vpn add NAME FILE             импорт/замена полного AWG .conf
  e-dev vpn remove NAME               удалить профиль
  e-dev vpn rename OLD NEW            переименовать, сохранив роли

Имя: буквы, цифры, дефис и подчёркивание, до 32 символов.
Список меню строится из текущих конфигов; названия серверов не вшиты.
Удалить выбранный, основной или резервный нельзя: сначала изменить выбор.
Повторный add с тем же именем заменяет ключ; активный профиль перезапускается.
On/Off сохраняется после перезагрузки. Выбор сервера при VPN off меняет
настройки, но сам туннель не включает. Auto при VPN off не проводит замеры.

Выбор сервера ОБЩИЙ для AP в режиме VPN/Hybrid и всех VPN-контейнеров.
Гибридные исключения действуют только для AP. Сам Pi и профиль контейнеров
default используют провайдера. Wi-Fi VPN OFF (DIRECT) меняет только маршрут AP.
VPN off закрывает VPN-контейнеры и VPN-часть AP; прямые исключения могут
работать по IP, но DNS гибрида использует туннель. Для обычного интернета
точки при VPN off выбирайте также wifi vpn off.

Ключи root-only: /etc/e-dev/profiles. Status не печатает ключи.
Свежий handshake и проверка связи важнее наличия интерфейса awg0.
Список ключей и выбор серверов доступны в разделе vpn.
```

## wifi

```text
МАРШРУТИЗАЦИЯ ТОЧКИ ДОСТУПА

  e-dev wifi vpn on                весь интернет AP через общий VPN
  e-dev wifi vpn off               весь интернет AP через провайдера
  e-dev wifi hybrid            российские IP/исключения напрямую, остальное VPN
  e-dev wifi status            AP, режим трафика, профиль туннеля
  e-dev wifi mode              меню VPN / DIRECT / HYBRID
  e-dev wifi mode vpn|direct|hybrid  выбрать маршрут без меню
  e-dev wifi check DOMAIN      проверить маршрут IPv4 домена
  e-dev wifi check IP          проверить маршрут конкретного IPv4
  e-dev wifi hybrid settings   интерактивное меню настроек гибрида
  e-dev wifi update            обновить RU IP-базу сейчас

Режим AP сохраняется после перезагрузки. Смена режима AP не перезапускает
VPN и не включает выключенный туннель. Выбор VPN — e-dev vpn settings.

В гибриде назначения сверяются с локальными российскими IP-сетями IPdeny,
доменно разрешёнными исключениями и своими прямыми IP/CIDR. Остальное VPN.
Кэш базы работает без интернета; сеть нужна только для её обновления.
Обновление ежедневное, при ошибке предыдущая рабочая база сохраняется.
Включены .ru/.su/.рф и вспомогательные домены Ozon, WB, Госуслуг и 2ГИС.

Настройки команды без меню:
  e-dev wifi hybrid settings show
  e-dev wifi hybrid settings domains list|add DOMAIN|del DOMAIN
  e-dev wifi hybrid settings ips list|add IPv4/CIDR|del IPv4/CIDR
  e-dev wifi hybrid settings geo on|off|status|update
  e-dev wifi hybrid settings autoupdate on|off|status
  e-dev wifi hybrid settings dns 1.1.1.1 8.8.8.8
  e-dev wifi hybrid settings check DOMAIN/IP

Geo off отключает учёт RU-базы, оставляя свои IP и доменные правила.
Autoupdate off отключает загрузку базы по расписанию; ручная update работает.
Ips — публичные IPv4 или сети не шире /8.
Домены задаются без https:// и пути; правило включает поддомены.
Изменения правил применяются сразу; приложения и старые соединения
могут потребовать переподключения. Settings не включает режим hybrid.
Старое wifi bypass list/add/del управляет тем же списком доменов.

DNS по умолчанию: 1.1.1.1 и 8.8.8.8. В VPN/Hybrid — через awg0,
в прямом AP — через провайдера. Изменение DNS применяется сразу в VPN/
Hybrid, в прямом AP — при следующей активации точки. TCP/UDP 53
перехватывается на Pi. DoH/Private Relay обходит доменную классификацию,
но RU IP-база и свои IP-правила продолжают действовать.
IPv6 в AP/VPN-сети отключён.

Классификация по IP не гарантирует доступ ко всем российским приложениям:
общие IP CDN могут обслуживать разные сайты, зарубежные CDN российских
сервисов требуют своих исключений. Проверьте фактические адреса сервиса.
Настройки гибрида не затрагивают выбор VPN-сервера или его режим Auto.
VPN-контейнеры используют общий туннель целиком, без AP-исключений.


WI-FI E-DEV

Начальная сеть AP: 10.42.0.1/24. Текущие адреса: e-dev links.
Защита: WPA2/RSN + CCMP (AES); WPA/TKIP запрещены.

  e-dev wifi clients          реальные подключённые устройства, IP/MAC
  e-dev wifi settings         меню адреса Pi, подсети и DHCP
  e-dev wifi settings show    текущая сеть и диапазон DHCP
  e-dev wifi settings network 192.168.50.1/24
  e-dev wifi settings network 192.168.50.1/24 192.168.50.100 192.168.50.200
  e-dev wifi settings dhcp auto
  e-dev wifi settings dhcp 192.168.50.100 192.168.50.200
  e-dev wifi settings lease 7200
  e-dev passwd wifi           новый пароль AP; клиенты переподключатся

network без диапазона включает автоматический DHCP-пул. lease 0 = 1 час.
Частные сети /16–/28; пересечение с LAN/VPN/контейнерами запрещено.
Применение выполняет служба e-dev-wifi-apply, даже если SSH оборвётся.
AP переподключится; клиенты получат новые адреса. Режим и сервер VPN
сохраняются, маршруты и DNS обновляются. Ошибка вызывает откат.
Проверить результат: settings show и journalctl -u e-dev-wifi-apply.
Если откат не удался, трафик AP закрыт: исправить через Ethernet.

Старые DHCP-записи показаны отдельно и не входят в число клиентов.
Имя/сигнал показываются, если устройство и драйвер их сообщают.
Скорость из iw — скорость радиосоединения, не замер интернет-скорости.

Если iPhone помнит предупреждение о WPA: забыть E-DEV, подключиться заново.
Сейчас встроенный wlan0 раздаёт AP, интернет приходит через Ethernet.

USB-адаптеры и резервирование: e-dev lan setup / e-dev help lan.
```

## lan

```text
СЕТЬ IN / OUT

  e-dev lan setup     псевдографическое меню интерфейсов и резервирования
  e-dev lan status    текущие зоны, активный вход и адреса
  e-dev lan check     проверить разрешённые входы сейчас

Управление: стрелки — выбрать, Enter — открыть, Space — отметить резервы,
Esc — назад. Терминал минимум 60×20. Изменения подтверждаются перед применением.

IN — источники интернета. eth0 закреплён в IN. USB Ethernet/Wi-Fi можно
добавить, выбрать DHCP или IPv4/маску/шлюз и DNS. Wi-Fi IN: список SSID,
ручной SSID, WPA2/WPA3/открытая сеть, скрытый ввод пароля.
Интерфейс подключается заранее, но не становится глобальным выходом,
пока не выбран основным или разрешённым резервным. Его маршрут изолирован.

OUT — общая локальная сеть на мосту edevbr0. Встроенный wlan0 закреплён
в OUT. Дополнительные Ethernet-порты и Wi-Fi AP (если поддерживает драйвер)
получают тот же пул DHCP, доступ к панелям/SMB и режим VPN ON/OFF/HYBRID.
Адрес и DHCP всего OUT: пункт меню OUT · подсеть и DHCP / e-dev wifi settings.
Wi-Fi адаптер в IN работает клиентом; в OUT — точкой, не клиентским мостом.

Резервирование: отдельно выбрать основной, отметить резервные, задать
порядок и включить автопереход. По умолчанию резервов нет, автопереход ВЫКЛ.
Проверяется HTTPS через каждый разрешённый вход. Три неудачи подряд —
следующий доступный резерв; физическое исчезновение — немедленный переход.
Возврат на основной после трёх успешных проверок. Проверки примерно каждые
20–30 секунд; время зависит от количества интерфейсов и таймаутов.
Если автопереход выключен, резервные не используются. Балансировки нет.
При потере всех разрешённых выходов неизвестный вход не подхватывается.

Выбор VPN-сервера отдельный и общий для AP/контейнеров: e-dev vpn settings.
При смене IN туннель переподключается, его профиль/режим выбора сохраняется.
Роли привязаны к постоянным MAC: смена USB-порта/имени не меняет назначение.
Настройки живут на Pi, восстановление и проверки запускает systemd.
Пароли Wi-Fi IN только в root-only NetworkManager keyfile, не в справочнике.

Применение выполняет e-dev-lan-apply независимо от SSH. При ошибке — откат;
если откат не подтверждён, OUT-трафик закрыт. Исправить через Ethernet или
локальный монитор/клавиатуру. Снимки /opt/e-dev/backups/lan-* содержат секреты.
Журнал: sudo journalctl -u e-dev-lan-apply -u e-dev-network -u e-dev-uplink.
Дополнительные USB-адаптеры и реальный переход между ними проверяются
после подключения оборудования; драйвер должен поддерживаться Pi OS.
```

## panels

```text
ПАНЕЛИ

  e-dev links                 актуальные IP и ссылки

Парольная LXConsole: https://<текущий-IP-Pi>:9443/
Incus UI: https://<текущий-IP-Pi>:8443/ui/ (клиентский сертификат браузера).
links показывает фактические IPv4 LAN/AP; старые адреса не подставляет.
Обе панели управляют одним Incus; контейнеры и профили общие.

LXConsole: пользователь user; пароль меняется через e-dev passwd ui.
Incus UI: пароль от SSH не используется; нужен зарегистрированный
клиентский сертификат браузера. Сертификат root@E-DEV не выбирать
вместо E-DEV Safari. Сертификат серверного TLS и клиентский сертификат
доступа имеют разные роли. На новом устройстве удобнее LXConsole.

IP eth0 выдаёт роутер по DHCP и может меняться; вызовите links снова.
```

## passwd

```text
ПАРОЛИ

  e-dev passwd all            SSH, SMB, Wi-Fi AP и LXConsole
  e-dev passwd ssh            SSH пользователя user
  e-dev passwd files          SMB user
  e-dev passwd wifi           пароль точки E-DEV
  e-dev passwd ui             LXConsole user

Команда запросит sudo, затем новый пароль дважды. Ввод скрыт.
Минимум 8 символов. Incus UI использует сертификат и пароля не имеет.
Изменение all последовательное: при сбое предыдущие изменения сохраняются.
Изменение Wi-Fi переподключает AP. Пароли в справочнике не сохраняются.
```

## containers

```text
КОНТЕЙНЕРЫ INCUS

  e-dev containers
  e-dev container start NAME
  e-dev container stop NAME

default: incusbr0, 10.158.92.0/24, напрямую.
vpn: vpnbr0, 10.43.0.0/24, только через общий awg0.
Default / Manual / Auto выбирают сервер одновременно для AP и этого
профиля. Для контейнера vpn российские AP-исключения не действуют.
VPN off закрывает VPN-контейнерам интернет. Wi-Fi VPN OFF (DIRECT) влияет только на AP.
Локальные адреса доступны согласно локальным маршрутам.

Установщик не создаёт тестовые контейнеры.
Лимит профилей по умолчанию 1 GiB RAM / 2 CPU; Pi имеет 4 GiB RAM.

Перенос Pi ARM ↔ PVE x86: Git переносит исходники и конфигурацию,
а контейнер создаётся под целевую архитектуру и пакеты собираются заново.
Готовый ARM rootfs нельзя просто загрузить как x86 LXC.
Реальный перенос проекта ещё не тестировался.
```

## troubleshoot

```text
ДИАГНОСТИКА

  e-dev status
  e-dev vpn status
  e-dev vpn speeds
  e-dev wifi clients
  e-dev wifi check DOMAIN/IP
  e-dev wifi hybrid settings show
  sudo systemctl list-timers 'e-dev-*'
  sudo journalctl -u e-dev-vpn -u e-dev-dns -u e-dev-vpn-health -u e-dev-auto -n 50 --no-pager

Журнал сохраняется между загрузками: лимит 64 MiB, срок до 7 дней.
После сбоя перезапуска: sudo journalctl -b -1 -n 100 --no-pager.
Один успешный reboot не исключает повторения сбоя.

VPN-связь отсутствует: проверить upstream, handshake и vpn status.
Manual не переключается сам; выберите другой через e-dev vpn manual.
Default использует основной/резерв; Auto — результаты замеров и проверку связи.
Сам Pi выходит напрямую. AP ON/HYBRID + VPN OFF: vpn on запускает туннель;
wifi vpn off переводит только AP на прямой выход.

Сбой Auto/Speedtest: посмотреть vpn speeds и журнал e-dev-auto.
Неудачный тест не разрешает прямой выход для VPN-трафика.
Без интернета автообновление RU-базы не удаляет рабочий локальный кэш.
Если российский сервис не работает, проверить его домены/IP, обновить
IP-базу, при необходимости добавить вспомогательные адреса сервиса.

Обновления устройств Meta могут зависеть от доступности их сервисов.
MSS AWG TCP ограничен 1360.
Реальные приложения Ozon/WB/2ГИС, фото с iPhone и полный цикл питания
проверяются на устройствах пользователя отдельно от маршрутизации.
```
