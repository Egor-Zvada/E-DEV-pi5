# Маршрутизация E-DEV

```text
                 Ethernet / позднее USB Wi-Fi
                            │
                      сеть провайдера
                            │
                     Raspberry Pi 5
                   ┌────────┴──────────┐
            основной маршрут       AWG awg0
              (table main)        (table 1042)
                   │                   │
           Pi, Incus default       Incus vpn
                   │                   │
                   └───── Wi-Fi AP ────┘
                      DIRECT / VPN / HYBRID
```

| Сеть / интерфейс | Адрес | Маршрут интернета |
|---|---|---|
| OUT `edevbr0` (AP `wlan0` + USB порты) | Изначально `10.42.0.1/24`, настройка `wifi settings` | Выбранный режим AP |
| Incus `vpnbr0` | `10.43.0.1/24` | Общий VPN всегда |
| Incus `incusbr0` | `10.158.92.1/24` | Провайдер |
| `eth0`, USB IN | DHCP / статика | Собственные таблицы 5000–5099; активный → main |
| `awg0` | Из выбранного `.conf` | В table 1042, не default route Pi |

Подсеть AP хранится в `/etc/e-dev/wifi.json`; сети контейнеров фиксированы. LAN берётся из подключённых kernel routes физических интерфейсов при `vpn boot/on`, смене AP-режима или подсети AP. Чужой туннель не добавляется в список прямых локальных сетей. Настройки исходного AWG-конфига `DNS`, `Table`, hooks удаляются; в runtime используется `Table=off`, IPv4 `AllowedIPs=0.0.0.0/0`. Для работы необходим userspace TUN `/dev/net/tun`.

`e-dev settings → AP → Подсеть и DHCP` меняет IPv4 Pi, подсеть, пул и аренду DHCP средствами NetworkManager. Применение запускается отдельной systemd-службой, поэтому не зависит от сохранения SSH-соединения. Перед переходом `inet e_dev_wifi_change` закрывает весь forwarded трафик `wlan0`/`edevbr0`. После активации AP обновляются source rules, guard, NAT и DNS; временный запрет снимается в конце. При ошибке восстанавливаются прежние настройки; если откат не удался, запрет сохраняется. Снимок настроек — `/opt/e-dev/backups/wifi-*`. Guard также отбрасывает IPv4 с чужим source subnet на AP/VPN-мосте.

## Защита при отказе

Table 1042 всегда содержит `blackhole default metric 32760`; при рабочем туннеле добавляется `default dev awg0 metric 10`. Исчезновение интерфейса не разрешает провайдерский fallback для защищённых источников. Дополнительно `inet e_dev_guard` разрешает для этих источников только локальные сети/туннель и прямые исключения AP в HYBRID; остальное отбрасывает. На загрузке guard применяется **до NetworkManager**. Скрипт не очищает весь nft ruleset: Incus и NM сохраняют свои таблицы.

| ip rule priority | Назначение |
|---|---|
| 10000–10099 | `oif` IN → собственная таблица (проверка резервов) |
| 10100–10199 | Локальный IPv4 IN → собственная таблица (обратный путь) |
| 10419 | AP `fwmark 0x42` → main, только HYBRID |
| 10420 | AP source → 1042, кроме DIRECT |
| 10421 | VPN-контейнеры source → 1042 |
| 10422 | Выход `oif awg0` → 1042, в том числе привязанный DNS/Speedtest |
| 10424 | Временный `oif edevprobe` → 1044 для проверки другого сервера |

Для HYBRID nft сохраняет `ct mark 0x42` и восстанавливает packet mark на ответах. `rp_filter=2` и `src_valid_mark=1` нужны для корректного обратного пути. AP/Incus IPv6 отключён; guard блокирует forwarded IPv6 AP и VPN-моста. TCP MSS ограничен 1360 в обоих направлениях AWG, чтобы уменьшить проблемы фрагментации.

## DNS / гибрид

DNS защищённых источников перехватывается на текущий IP AP, порт `1053` (изначально `10.42.0.1:1053`). Отдельный dnsmasq отправляет запросы в заданные DNS с привязкой к `awg0`. Домены прямых исключений наполняют `inet e_dev_split ru4` с timeout 1h. Постоянные RU CIDR находятся в `rusubnets`, собственные IP/CIDR — в `custom4`. Только AP использует эти множества для прямого выхода.

DIRECT AP пользуется DNS NetworkManager с настройками `/etc/NetworkManager/dnsmasq-shared.d/e-dev-upstream.conf`; VPN-контейнеры всё равно используют туннель. Изменение direct DNS применяется при следующей активации AP. Обновление GeoIP использует атомарную nft-транзакцию и замену кеш-файла; ошибка скачивания не удаляет предыдущий список. Нет обязательного обращения к внешней базе на каждый запрос.

## Автономные службы

`e-dev-vpn` восстанавливает режим/выбранный профиль; `e-dev-awg-go@awg0` держит Go daemon в отдельной systemd cgroup. Health и Auto имеют отдельный policy lock; health пропускает занятой контроллер, Auto ждёт. Root service задаёт HOME для Ookla. Временный `edevprobe` имеет собственную таблицу/правило, удаляемые в `finally`; дубликат с теми же ключами/endpoint не запускается параллельно, чтобы не менять endpoint peer.

Auto ранжирует download, затем ping, и проверяет, что Speedtest действительно использовал адрес нужного интерфейса. Если все замеры неуспешны, сохраняются активный профиль и прежний рейтинг. Default пробует только заданные основной/резерв. Manual не переключается автоматически. Наличие `awg0` само по себе не доказывает соединение; health проверяет HTTPS через него.

Системные изменения требуют root; профили/приватные сертификаты локальны. Членство в `incus-admin` предоставляет административный доступ к хосту. Панели предназначены для домашней LAN/AP: не публикуйте порты 8443/9443/445 через роутер без отдельной настройки доступа.

## Физические IN / OUT

`e-dev settings → LAN / OUT` управляет физическими устройствами NetworkManager через dialog. Встроенные `eth0`/`wlan0` закреплены; дополнительные привязаны к постоянному MAC, а не меняющемуся имени. `edevbr0` несёт прежний IP AP и shared DHCP; OUT-порты имеют IPv4 disabled и controller bridge. Wired OUT и AP используют одну подсеть, DNS и guard. Wi-Fi IN работает в infrastructure, OUT — AP; обычный Wi-Fi client в мост OUT не включается.

Каждый IN сохраняет connected/default routes в собственной таблице 5000–5099. В main копируются локальные сети с protocol 241. Выбранный default имеет metric 40; постоянный blackhole default metric 41 предотвращает подхват случайного main default с обычной NM-метрикой. Проверки HTTPS привязаны к устройству и используют literal IP без DNS-зависимости. Не выбранный в основной/резерв IN не становится глобальным выходом. Отрицательный DNS priority выбранного входа исключает DNS остальных IN.

`e-dev-network` восстанавливает правила перед VPN; `e-dev-uplink.timer` проверяет входы после запуска. Failover по умолчанию выключен. При включении выбирает только основной и упорядоченные резервы: три провала для переключения, три успеха для возврата; исчезновение активного устройства учитывается сразу. Балансировки нет. Переключение обновляет локальные VPN-маршруты и переподключает выбранный AWG, сохраняя VPN Default/Manual/Auto.

`e-dev-lan-apply` выполняет изменение независимо от терминала, под network/policy/VPN locks. `inet e_dev_lan_change` временно блокирует forwarding OUT; после проверки IP и включения AP в мост запрет снимается. Откат восстанавливает NM keyfiles, конфиги, маршруты, DNS и SMB, затем проверяет ранее активные подключения и адрес OUT. Неуспешный откат оставляет запрет. Root-only снимок содержит секреты; публичный lan.json их не содержит.
