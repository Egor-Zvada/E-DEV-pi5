# Маршрутизация E-DEV

```text
                 Ethernet / позднее USB Wi-Fi
                            │
                      сеть провайдера
                            │
                     Raspberry Pi 5
                   ┌────────┴──────────┐
            основной маршрут       AWG awg0
              (table main)        (table 1042)
                   │                   │
           Pi, Incus default       Incus vpn
                   │                   │
                   └───── Wi-Fi AP ────┘
                      DIRECT / VPN / HYBRID
```

| Сеть / интерфейс | Адрес | Маршрут интернета |
|---|---|---|
| AP `wlan0` | `10.42.0.1/24` | Выбранный режим AP |
| Incus `vpnbr0` | `10.43.0.1/24` | Общий VPN всегда |
| Incus `incusbr0` | `10.158.92.1/24` | Провайдер |
| `eth0`, USB uplink | DHCP | Основной маршрут Pi |
| `awg0` | Из выбранного `.conf` | В table 1042, не default route Pi |

Внутренние подсети фиксированы. LAN берётся из подключённых kernel routes физических интерфейсов при `vpn boot/on` или смене AP-режима. Чужой туннель не добавляется в список прямых локальных сетей. Настройки исходного AWG-конфига `DNS`, `Table`, hooks удаляются; в runtime используется `Table=off`, IPv4 `AllowedIPs=0.0.0.0/0`. Для работы необходим userspace TUN `/dev/net/tun`.

## Защита при отказе

Table 1042 всегда содержит `blackhole default metric 32760`; при рабочем туннеле добавляется `default dev awg0 metric 10`. Исчезновение интерфейса не разрешает провайдерский fallback для защищённых источников. Дополнительно `inet e_dev_guard` разрешает для этих источников только локальные сети/туннель и прямые исключения AP в HYBRID; остальное отбрасывает. На загрузке guard применяется **до NetworkManager**. Скрипт не очищает весь nft ruleset: Incus и NM сохраняют свои таблицы.

| ip rule priority | Назначение |
|---|---|
| 10419 | AP `fwmark 0x42` → main, только HYBRID |
| 10420 | AP source → 1042, кроме DIRECT |
| 10421 | VPN-контейнеры source → 1042 |
| 10422 | Выход `oif awg0` → 1042, в том числе привязанный DNS/Speedtest |
| 10424 | Временный `oif edevprobe` → 1044 для проверки другого сервера |

Для HYBRID nft сохраняет `ct mark 0x42` и восстанавливает packet mark на ответах. `rp_filter=2` и `src_valid_mark=1` нужны для корректного обратного пути. AP/Incus IPv6 отключён; guard блокирует forwarded IPv6 AP и VPN-моста. TCP MSS ограничен 1360 в обоих направлениях AWG, чтобы уменьшить проблемы фрагментации.

## DNS / гибрид

DNS защищённых источников перехватывается на `10.42.0.1:1053`. Отдельный dnsmasq отправляет запросы в заданные DNS с привязкой к `awg0`. Домены прямых исключений наполняют `inet e_dev_split ru4` с timeout 1h. Постоянные RU CIDR находятся в `rusubnets`, собственные IP/CIDR — в `custom4`. Только AP использует эти множества для прямого выхода.

DIRECT AP пользуется DNS NetworkManager с настройками `/etc/NetworkManager/dnsmasq-shared.d/e-dev-upstream.conf`; VPN-контейнеры всё равно используют туннель. Изменение direct DNS применяется при следующей активации AP. Обновление GeoIP использует атомарную nft-транзакцию и замену кеш-файла; ошибка скачивания не удаляет предыдущий список. Нет обязательного обращения к внешней базе на каждый запрос.

## Автономные службы

`e-dev-vpn` восстанавливает режим/выбранный профиль; `e-dev-awg-go@awg0` держит Go daemon в отдельной systemd cgroup. Health и Auto имеют отдельный policy lock; health пропускает занятой контроллер, Auto ждёт. Root service задаёт HOME для Ookla. Временный `edevprobe` имеет собственную таблицу/правило, удаляемые в `finally`; дубликат с теми же ключами/endpoint не запускается параллельно, чтобы не менять endpoint peer.

Auto ранжирует download, затем ping, и проверяет, что Speedtest действительно использовал адрес нужного интерфейса. Если все замеры неуспешны, сохраняются активный профиль и прежний рейтинг. Default пробует только заданные основной/резерв. Manual не переключается автоматически. Наличие `awg0` само по себе не доказывает соединение; health проверяет HTTPS через него.

Системные изменения требуют root; профили/приватные сертификаты локальны. Членство в `incus-admin` предоставляет административный доступ к хосту. Панели предназначены для домашней LAN/AP: не публикуйте порты 8443/9443/445 через роутер без отдельной настройки доступа.
